## 收尾提示残留原因与修复

r4在`_iter_llm_responses_with_fallback`候选请求路径处理上下文，并将深拷贝后的`candidate_messages`写回`run_context.messages`。旧清理按对象身份移除原临时提示，深拷贝对象不再是同一实例，因此残留在后续历史中。

新实现对当前请求的提示添加随机归属标记，支持深拷贝及序列化重建后的精确识别。正常、异常、取消与热重载都清理自身控制消息；同字的合法用户正文、混合正文、其他归属消息及原生截断结果保留，不通过恢复旧历史撤销截断。

收尾路径使用实例范围的r4适配：先按相同预算运行原生本地截断，再追加临时提示，最后用原生计数器检查包含提示的总预算。该路径不触发额外LLM摘要或自定义压缩器；预算仍不足时使用已有的如实兜底答复，不新增最终API调用。非收尾请求及`process=False`沿原逻辑。外部包装器保留的旧桥接仅更新本插件自身的失效转接，不覆盖外部包装器。

限定只读轮询的原策略不变：精确试点请求、严格只读元数据、单项成功JSON对象、相同参数及完整未完成结果连续3次后，至多一次无工具收尾。未知工具及有变化结果继续原流程，正常查询不增加模型调用。原人格与工具权限保持不变。
