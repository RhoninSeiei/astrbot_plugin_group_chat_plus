# 一次完成群聊参与和回复篇幅判断

目标：参考当前生产 Matoi 的 skip/brief/full 分类，保留人格、沉默、上下文及自然工具回复，消除普通群聊的串行粗筛和最终复判。不实现固定查询直出，不修改 Matoi、核心或提供商配置。

1. DecisionAI 保持原有 bool 接口，增加三分类模式。使用现有决策模型与人格配置，一次无工具请求同时决定参与和篇幅。事件保存分类，错误区别于真实 skip，旧 yes/no 模式兼容。
2. 主流程把现有最终判断开关兼容为统一分类开关，取消正式生成前第二次请求。@和非智能关键词沿用跳过判断的行为；分类只改变生成提示，不禁止工具、不硬截断正文。
3. 拟人、疲劳、概率、等待窗口和主动发言调度保留。真实 skip 统一经过现有拒绝/冷却/缓存路径；错误不记人格拒绝。正向效果仍在实际发送后计入一次。
4. 验证三态、错误、并发事件隔离、当前消息与追加消息完整保留、自定义提示与推理协议、工具能力、发送状态及已有主动发言检查。用相同生产核心做离线执行验证。
5. 审查后提交、推送、按精确清单备份和暂存，只对 Group Chat Plus 执行一次定向重载；核对哈希、注册、初始化及实际请求日志，不发送未授权测试消息。

语义取舍：原来的正式回复模型二次否决并入一次决策，沿用当前决策模型/人格配置；不再把第一轮 yes 当作“等待另一个模型再判断”的宽松放行。brief/full 均仍由正式模型生成自然回复，模型自行规划和解释工具结果。主动发言已有独立判断与调度，不增加三分类或改变沉默计时。
